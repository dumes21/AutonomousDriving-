# Handoff, 2026-10-21: where the JetRacer DQN project stands

**Not ready for physical driving.** The camera calibration is NOT validated, no measured steering map exists, and the throttle direction, e-stop,
deadman and safety gate have never been tested on hardware. Do not run `--enable-motors` until docs/FIRST_PHYSICAL_TEST.md sections A-C are complete.

## Done and checked (offline unless stated)
* Trained DQN: `experiments/dqn/20261020_151620_footprint_v1/final.zip` (also committed with its config/eval). Numpy export for the car:
  `inference/dqn_footprint_v1.npz` (matches SB3 greedy actions). Simulator evaluation (`eval/evaluate_dqn.py`, `results/dqn_evaluation_footprint_v1/`):
  0 % crashes, 4 whole laps, but 72 % crashes with observation noise sigma 0.01 and 100 % with one step (50 ms) of action delay. Brittle.
* Perception: Lab orange-boundary detector -> calibrated `StateEstimator` (offset m, heading rad, simulator signs) -> safety gate -> DQN
  (`car/drive_dqn.py`, DRY RUN by default). `car/camera_test_dqn.py` runs the same estimator offline on images and requires `--calibration`.
* Camera calibration 2026-10-21: `perception/calibration/20261021/CAL.json` (fitted/measured, no assumed parameters). **Not validated**: both +-2.5 cm
  photos miss by about 1.1 cm (guideline 1.0 cm); estimates are about 0.55x the true offset. Details and numbers: `perception/calibration/20261021/CALIBRATION_NOTES.md`.
  Calibration photos: `data/calibration_20261021/`.
* Live dry run on the Jetson (reported by Seth, log not committed): 100 frames of live camera through the whole pipeline with motors disabled,
  zero hardware commands issued. Python 3.6.15 + numpy 1.19.5 + OpenCV 4.5.5 on a laptop gave identical decisions to Python 3.12 (replay and fake-camera live branch).

## Reproduce the live dry run (motors disabled)
Files the car needs (only `car/drive_dqn.py`, with a print-only change, and `CAL.json` are new in this commit; the rest were already on the branch): `car/drive_dqn.py car/lane_detection.py
car/lane_observation.py perception/boundary_detector.py perception/ground_plane.py perception/state_estimator.py inference/dqn_policy.py
inference/pipeline.py inference/vehicle_adapter.py inference/dqn_footprint_v1.npz perception/calibration/20261021/CAL.json`. Then on the Jetson:
```
cd ~/seth-jetracer      # adjust to your clone
python3 --version       # 3.6.x
ps aux | grep -E "teleop_record|drive_model|drive_test|drive_dqn|camera_stream|camera_capture|jupyter|ipykernel" | grep -v grep   # camera must be free
mkdir -p /tmp/poison/jetracer && echo 'raise ImportError("jetracer must not be imported in a dry run")' > /tmp/poison/jetracer/__init__.py
PYTHONPATH=/tmp/poison python3 car/drive_dqn.py --calibration perception/calibration/20261021/CAL.json --camera --max-steps 100
```
Do NOT pass `--enable-motors`. The run writes `logs/dqn_dryrun_<time>.csv` (git-ignored). The last line must read `hardware commands issued: 0`.

## What the next person must do (in order; all MANDATORY before driving)
1. **Steering check, wheels raised, throttle never touched:** `python3 car/teleop_record.py --max-throttle 0.15 --steer-limit 0.8 --stream-port 0`, nudge with A/D (latched
   0.1 steps, never beyond +-0.8, do not press W/S), record: neutral (team estimate about +0.35), left (about -0.6), right (about +0.6). Check A turns left and D turns right.
2. **Steering map** (`STEER.json`, format in FIRST_PHYSICAL_TEST.md B.2): needs LEFT/STRAIGHT/RIGHT with equal turning radius, measured on the floor. None exists, so
   `drive_dqn.py --enable-motors` refuses to start. Never label estimated values `measured`.
3. **Throttle direction** (wheels raised, explicit confirmation first): which sign drives forward; use `--invert-throttle` accordingly. Minimum usable throttle (~0.10-0.12 reported);
   real speed vs the simulator's 0.6 m/s.
4. **E-stop, deadman and safety gate on the car** (code inspected only so far): X stops, releasing W stops after 0.5 s, covering the lens/one boundary gives STOP and a latched stop that needs re-arming.
   Note `teleop_record.py`'s deadman is separate code and does not verify `drive_dqn.py`'s.
5. **Finish the calibration validation:** +-5 cm, yaw +-5/+-10 deg, combined poses, a bend, re-placed repeats; consider lens-distortion calibration. Then run
   `car/camera_test_dqn.py --calibration ... ` (command in docs/CALIBRATION_DAY.md section 7).
6. Only then FIRST_PHYSICAL_TEST.md section D, on a short straight at the lowest usable throttle, one person on the stop key and one ready to lift the car.

## Known risks
Policy is brittle to noise/delay (above); the offset estimate is biased low; heading in bends is structurally biased (~0.1 rad); `JetRacerAdapter.stop()` is described as
"written twice" but returns after the first successful write (flagged, not changed); the motor path has never run on hardware.
